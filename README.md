# Эмулятор UNIX-оболочки — вариант №7

Учебный эмулятор командной строки UNIX-подобной ОС на **Java** с графическим
интерфейсом **Swing**. Каждый из пяти этапов сохранен отдельным коммитом.

Полная версия находится в [main](https://github.com/Sanamerskii/unix-emulator/tree/main)
и [stage-5](https://github.com/Sanamerskii/unix-emulator/tree/stage-5).
В main последовательно идут пять коммитов: REPL, конфигурация, VFS, основные
и дополнительные команды. Для проверки отдельного этапа переключайтесь на его ветку.

## Этапы и ветки

| Этап | Ветка | Реализованная функциональность |
| --- | --- | --- |
| 1. REPL | [stage-1](https://github.com/Sanamerskii/unix-emulator/tree/stage-1) | GUI, имя VFS в заголовке, парсер переменных окружения, обработка ошибок, заглушки ls/cd, exit |
| 2. Конфигурация | [stage-2](https://github.com/Sanamerskii/unix-emulator/tree/stage-2) | Параметры VFS и стартового скрипта, отладочный вывод, остановка скрипта при первой ошибке |
| 3. VFS | [stage-3](https://github.com/Sanamerskii/unix-emulator/tree/stage-3) | Загрузка ZIP в память, Base64 для двоичных данных, ошибки загрузки, разные варианты VFS |
| 4. Основные команды | [stage-4](https://github.com/Sanamerskii/unix-emulator/tree/stage-4) | Логика ls/cd, команды head и du |
| 5. Дополнительные команды | [stage-5](https://github.com/Sanamerskii/unix-emulator/tree/stage-5) | chown и touch с изменениями только в памяти, кнопка «Ввод» |

Каждая следующая версия включает функциональность предыдущих этапов.
Перед переключением ветки закройте окно эмулятора.

## Требования

- JDK 17 или новее: команды java и javac должны быть доступны в терминале.
- Git для получения репозитория и переключения веток.
- Графическая среда для запуска Swing.
- Для скриптов .sh — оболочка sh, доступная в macOS и Linux.

Внешние Java-библиотеки, Maven и Gradle не требуются. Репозиторий приватный:
для клонирования нужна авторизация GitHub и доступ к репозиторию.

## Быстрый запуск полной версии

В терминале выполните:

```sh
git clone https://github.com/Sanamerskii/unix-emulator.git
cd unix-emulator
git switch main
./fixtures.sh
./run.sh --vfs build/vfs/deep.zip --script demos/stage-5-success.txt
```

Если репозиторий уже скачан, перейдите в его директорию и начните с git switch main.
Все команды запуска выполняются **из папки проекта, где лежит run.sh**.

fixtures.sh создаст демонстрационные архивы в build/vfs. Откроется окно эмулятора,
в котором будут показаны параметры, команды стартового скрипта и их результаты.
После успешного завершения скрипта можно вводить команды вручную.

Для запуска без стартового скрипта:

```sh
./run.sh --vfs build/vfs/deep.zip
```

Введите команду в нижнюю строку окна и нажмите Enter или кнопку «Ввод».
Кнопка доступна в main и stage-5. Команда exit закрывает окно.

В терминал вставляйте только сами команды, без строк с тройными обратными кавычками.
Если появилась строка `bquote>`, нажмите Ctrl+C и повторите ввод.

## Параметры запуска

В stage-1 необязательный аргумент задает отображаемое имя VFS:

```sh
git switch stage-1
./run.sh training-vfs
```

В stage-2–stage-5 используются два параметра:

| Параметр | Назначение |
| --- | --- |
| --vfs PATH | Путь к физическому расположению VFS; начиная с этапа 3 — к ZIP-архиву |
| --script PATH | Путь к стартовому скрипту UTF-8 |

Оба параметра необязательны. На этапе 2 путь VFS только принимается и выводится;
архив еще не загружается. Начиная с этапа 3, без --vfs создается пустая VFS в памяти.
Без --script приложение сразу готово к интерактивному вводу.

Пути с пробелами заключайте в кавычки:

```sh
./run.sh --vfs "build/vfs/VFS with spaces.zip" --script demos/stage-5-success.txt
```

Все заданные параметры отображаются в терминале запуска и в окне.
Заголовок окна содержит имя VFS. Неизвестные или повторные параметры,
отсутствующее значение и пустой путь вызывают ошибку.

run.sh переходит в директорию проекта, поэтому относительные пути параметров
разрешаются от нее. При прямом запуске Java они разрешаются от текущей директории.

## Парсер и стартовый скрипт

Парсер поддерживает раскрытие `$NAME` и `${NAME}` из окружения
реальной ОС, кавычки, экранирование обратной косой чертой и пустые аргументы.
Одинарные кавычки сохраняют текст буквально, двойные допускают раскрытие переменных.
Неопределенная переменная раскрывается в пустую строку.

Например, `cd "$HOME"` использует HOME реальной ОС, но получившийся путь ищется
**внутри VFS**. Если такого виртуального каталога нет, будет показана ошибка.
Пути команд не дают доступа к файлам реальной ОС.

Стартовый скрипт выполняется построчно. Пустые строки и строки, начинающиеся
с # после пробелов, пропускаются. На экране видны и ввод, и вывод команд.

- При первой ошибке скрипт останавливается; сообщается его путь и номер строки.
- После ошибки остается доступен интерактивный ввод.
- exit прекращает выполнение скрипта и закрывает окно.
- Ошибка чтения скрипта также отображается в окне.

## Команды

В stage-1–stage-3 команды ls и cd являются заглушками: выводят имя и аргументы.
Начиная с stage-4, они выполняют операции в виртуальной файловой системе.

| Команда | Доступна с этапа | Поведение |
| --- | --- | --- |
| ls [путь] | 1; логика с 4 | Имена в текущем или заданном каталоге; для файла — его имя |
| cd [путь] | 1; логика с 4 | Переход по абсолютному или относительному пути; без аргумента — в / |
| exit | 1 | Закрытие окна без аргументов |
| head файл | 4 | Первые 10 строк файла UTF-8 |
| du [путь] | 4 | Рекурсивные размеры каталогов; без аргумента — текущий каталог |
| touch файл | 5 | Создание пустого файла или обновление времени изменения существующего |
| chown владелец путь | 5 | Изменение виртуального владельца файла или каталога |

Для cd поддерживаются `.` и `..`. Имена с пробелами требуют кавычек.
Расширенные опции команд не реализованы.

du выводит KiB: сумма логических байтов файлов округляется вверх до 1024 байт.
Каталоги сами занимают 0 байт; размер сжатого ZIP не учитывается.
touch не изменяет содержимое существующего файла. Для создания файла
его родительский каталог должен существовать.

Успешные cd, touch и chown не выводят сообщений. Созданный файл виден через ls.
Владелец хранится в VfsNode; изменение проверяется тестом, учетные записи реальной ОС
не меняются.

Пример интерактивного диалога после загрузки deep.zip. Эти команды вводятся
**в окне эмулятора**, а не в терминале macOS/Linux:

```text
ls
cd docs
head guide.txt
touch created.txt
ls
chown student created.txt
du .
cd ..
exit
```

Для проверки ошибок можно ввести неизвестную команду pwd, команду cd с двумя
путями или head без аргумента. Ошибка не закрывает окно.

## Виртуальная файловая система

Начиная с этапа 3, VFS читается из ZIP-архива без распаковки.
Файлы и каталоги хранятся в памяти; двоичные данные представлены в Base64.
Отсутствующий файл, неверный формат или поврежденный ZIP вызывают ошибку запуска.

fixtures.sh создает только локальные демонстрационные файлы:

| Архив | Содержимое |
| --- | --- |
| build/vfs/minimal.zip | Минимальная VFS: пустой корневой каталог |
| build/vfs/several.zip | Несколько файлов, включая двоичный |
| build/vfs/deep.zip | Файлы и каталоги с тремя уровнями вложенных папок a/b/c |
| build/vfs/VFS with spaces.zip | Вариант для проверки пути с пробелами |
| build/vfs/invalid.zip | Заведомо неверный формат для проверки ошибки |

Архивы и результаты сборки находятся в игнорируемой папке build/ и не добавляются в Git.

Все изменения touch/chown выполняются только в памяти. Исходный ZIP остается
неизменным. При повторном запуске созданные файлы исчезают, владелец и время
изменения возвращаются к данным новой загрузки.

## Демонстрация этапов

Сначала перейдите в папку репозитория и выберите нужную ветку.
Сценарии более ранних этапов запускайте в соответствующих ветках:
поведение заглушек отличается от полной версии.

| Ветка | Сценарии реальной ОС |
| --- | --- |
| stage-2 | ./scripts/stage-2-parameters.sh и ./scripts/stage-2-errors.sh |
| stage-3 | ./scripts/stage-3-vfs.sh и ./scripts/stage-3-errors.sh |
| stage-4 | ./scripts/stage-4-commands.sh |
| stage-5 | ./scripts/stage-5-commands.sh |

Например:

```sh
git switch stage-4
./scripts/stage-4-commands.sh
```

Этап 1 проверяется интерактивно: ls, cd "$HOME", неизвестная команда,
неверное число аргументов, незакрытая кавычка и exit.

Сценарии этапов 3–5 сами вызывают fixtures.sh. Закрывайте каждое открытое окно,
чтобы сценарий перешел к следующему запуску. Вход и результат каждой команды
отображаются в GUI. Ошибочные случаи вынесены в отдельные стартовые скрипты,
поскольку каждый скрипт останавливается на первой ошибке.

## Тесты

В любой ветке этапа выполните:

```sh
./test.sh
```

Скрипт компилирует приложение и выполняет тесты без GUI.
При ошибке он завершается с ненулевым кодом. Проверяются только требования
соответствующей версии:

- Этап 1: парсер, команды REPL, ошибки и exit.
- Этап 2: параметры запуска, вывод и остановка стартового скрипта.
- Этап 3: варианты ZIP VFS, двоичные данные и ошибки загрузки.
- Этап 4: ls, cd, head и du.
- Этап 5: touch, chown, сохранность содержимого и неизменность ZIP.

Графический интерфейс демонстрируется отдельно, интерактивно и через сценарии scripts/.

## Структура репозитория

```text
src/emulator/       исходный код Java
tests/emulator/     проверки требований и генератор демонстрационных ZIP
demos/              стартовые скрипты эмулятора
scripts/            демонстрационные сценарии реальной ОС
run.sh              сборка и запуск GUI
test.sh             сборка и запуск тестов
fixtures.sh         подготовка ZIP для этапов 3–5
.gitignore          исключение результатов сборки и архивов
README.md           общая документация
```

Папки demos/scripts появляются со второго этапа, fixtures.sh — с третьего.
Коммиты оформлены по Conventional/Scoped Commits с описанием конкретных изменений.
